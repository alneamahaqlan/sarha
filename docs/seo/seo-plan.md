# خطة تحسين محركات البحث (SEO) — دليل المجمعات الطبية

> **الحالة:** مسودة للنقاش — لم يُنفَّذ أي كود بعد.
> **آخر تحديث:** 2026-06-10
> **النطاق المبدئي:** المنطقة الشرقية — الدمام، الخبر، الظهران، القطيف، سيهات.
> **الهدف:** نمو عضوي متوازن (جذب المرضى/الباحثين **B2C** + جذب المجمعات للتسجيل **B2B**).

---

## 1. الملخص التنفيذي والاستراتيجية

المنصة منصة **دليل (directory/marketplace)** وليست موقع شركة. لذلك ـ خلافاً للمواقع العادية ـ تأتي **أغلب قيمة الـ SEO من Programmatic SEO**: توليد آلاف الصفحات المنظمة آلياً من البيانات الموجودة، لا من كتابة محتوى يدوي.

الاستراتيجية المعتمدة بناءً على النقاش:

1. **رأس جسر إقليمي (Regional Beachhead):** السيطرة على نتائج البحث في مدن المنطقة الشرقية أولاً قبل التوسع وطنياً. التركيز يرفع الكثافة (عدد المجمعات لكل صفحة تقاطع) فتصبح الصفحات قوية لا فارغة، ويبني سلطة محلية يصعب على المنافسين الوطنيين منافستها محلياً.
2. **توازن B2C + B2B:** مسارا كلمات مفتاحية متوازيان — مسار المرضى (يبحثون عن عيادات/عروض/أسعار) ومسار المجمعات (يبحثون عن "كيف أسجّل عيادتي"، "منصة حجوزات للعيادات").

**معيار النجاح المبكّر:** أن نتصدّر عبارات مثل «أفضل مجمعات الأسنان في الخبر»، «عروض تجميل الدمام»، «عيادات جلدية القطيف» خلال 3–6 أشهر، لأن المنافسة المحلية عليها أضعف بكثير من العبارات الوطنية.

## 3. بنية المعلومات وصفحات التقاطع (جوهر الخطة)

هذه أهم نقطة في الخطة كلها. الفكرة: تحويل خيارات الفلترة في البحث إلى **صفحات هبوط ثابتة الروابط (clean URLs) قابلة للفهرسة**.

### 3.1 نموذج البيانات المتاح (مؤكَّد من الكود)

- `City` (الدمام/الخبر/…) — `belongsTo` من `Clinic`. ⚠️ **لا يملك حقل `slug`** حالياً ([City.php](../../app/Models/City.php)).
- `Category` (التخصصات: أسنان/جلدية/تجميل…) — `belongsToMany` مع `Clinic` عبر `clinic_categories`، **ويملك `slug`** أصلاً ([Category.php](../../app/Models/Category.php)).
- `Clinic` → `hasMany` Service / Doctor / Offer / Article.

### 3.2 أنواع الصفحات المقترحة (هرمية)

```
/                                         الرئيسية
/الشرقية                                  صفحة المنطقة (hub)            ← جديد
/الشرقية/الخبر                            صفحة المدينة (كل التخصصات)    ← جديد
/الشرقية/الخبر/اسنان                       تقاطع مدينة×تخصص ★★★          ← جديد (الكنز)
/الشرقية/الخبر/اسنان/عروض                  تقاطع + نية شرائية (عروض)     ← جديد
/clinic/{slug}                            صفحة المجمع                  ✅ قائم
/clinic/{slug}/doctor/{doctor}            صفحة الطبيب                  ✅ قائم
/clinic/{slug}/offer/{offer}              صفحة العرض                   ✅ قائم
```

**قرار تصميم الروابط (يحتاج حسماً):**
- خيار أ — slug عربي مقروء: `/الشرقية/الخبر/اسنان` (أقوى دلالياً للجمهور السعودي، يتطلب URL encoding سليم).
- خيار ب — slug لاتيني: `/eastern/khobar/dental` (أنظف تقنياً، أضعف دلالياً عربياً).
- **توصيتي:** عربي للـ ar ولاتيني للـ en، مع ربطهما عبر `hreflang`.

### 3.3 لماذا صفحات منفصلة بدل `?city=&category=`؟

- البحث الحالي يعتمد redirect مبني على **الجلسة** (`search_filters`) → نفس الرابط يعطي نتائج مختلفة لكل زائر → غير صالح للفهرسة.
- query params تُعامَل غالباً كصفحة واحدة مكرّرة.
- صفحة `مدينة×تخصص` ثابتة الرابط يمكن أن تحمل: عنوان H1 فريد، نص تعريفي، قائمة المجمعات، عروضها، أسئلة شائعة، Schema `ItemList` — أي كل مقومات التصدّر.

### 3.4 تجنّب الصفحات الفارغة (Thin/Doorway pages)

خطر Programmatic SEO الأكبر هو توليد صفحات بلا محتوى كافٍ (عقوبة جوجل). الضوابط:
- لا تُنشأ صفحة تقاطع إلا إذا كان فيها **حد أدنى (مثلاً ≥ 3 مجمعات)**.
- صفحات أقل من الحد → `noindex` أو redirect لصفحة المدينة الأعلى.
- نص تعريفي فريد (ليس قالباً مكرراً حرفياً) + بيانات حقيقية (متوسط الأسعار، عدد المجمعات، أبرز العروض).

## 4. الجوانب التقنية (Technical SEO)

### 4.1 `hreflang` (أولوية قصوى — P0)
إضافة وسوم بديلة لكل صفحة في [public.blade.php](../../resources/views/layouts/public.blade.php):
```html
<link rel="alternate" hreflang="ar" href="{النسخة العربية}">
<link rel="alternate" hreflang="en" href="{النسخة الإنجليزية}">
<link rel="alternate" hreflang="x-default" href="{الافتراضي}">
```
يتطلب أن يعرف كل مسار نسخته في اللغة الأخرى (تبديل اللغة موجود عبر `/lang/{locale}`).

### 4.2 توسعة الـ sitemap (P0)
في [SitemapController.php](../../app/Http/Controllers/SitemapController.php):
- إضافة: العروض، الخدمات، الأطباء، الباقات، الفروع، فهرس المقالات `/articles`، صفحة المقارنة، لوحة طلبات التسعير، **وصفحات التقاطع الجديدة**.
- إضافة وسوم `xhtml:link` لـ hreflang داخل الـ sitemap نفسه.
- مع نمو الحجم: التحول إلى **sitemap index** مقسّم (مجمعات/أطباء/عروض/مقالات/تقاطعات) — الحد الحالي 5000 لكل نوع كافٍ مرحلياً.

### 4.3 إصلاح `robots.txt` (P0)
- إزالة `/login` من الـ sitemap (تناقض)، والإبقاء على منعه في robots.
- إضافة منع لمسارات النتائج المفلترة بالـ params لتجنّب تبديد ميزانية الزحف: `Disallow: /search?` (مع إبقاء صفحات التقاطع النظيفة مسموحة).
- إضافة منع `/cart`, `/account`, `/compare` (محتوى شخصي/مكرر لا قيمة فهرسية له).

### 4.4 العناوين الوصفية الفريدة (P0)
التأكد أن كل صفحة فرعية تستخدم `@section('title')` و`@section('description')` بقيم فريدة ديناميكية:
- المجمع: «{اسم المجمع} — {المدينة} | {التخصصات}».
- العرض: «{اسم العرض} بسعر {السعر} — {المجمع}، {المدينة}».
- التقاطع: «أفضل مجمعات {التخصص} في {المدينة} — الأسعار والعروض».

### 4.5 توسعة Structured Data / JSON-LD (P1)
| الصفحة | النوع المقترح |
|--------|---------------|
| الطبيب | `Physician` |
| العرض | `Offer` / `Product` مع `priceSpecification` |
| الخدمة | `MedicalProcedure` أو `Service` + `Offer` |
| المقال | `Article` / `MedicalWebPage` |
| كل الصفحات | `BreadcrumbList` (فتات التنقّل) |
| التقاطع | `ItemList` (قائمة المجمعات) |
| الأسئلة الشائعة | `FAQPage` |
| الموقع كله | `Organization` + `WebSite` مع `SearchAction` (مربع بحث في النتائج) |

### 4.6 الأداء و Core Web Vitals (P2)
- الخطوط: استخدام `font-display: swap` (موجود) + `preload` للخطوط الحرجة + التفكير في self-hosting لتقليل الاعتماد على Google Fonts.
- الصور: `loading="lazy"` + أبعاد صريحة (تفادي CLS) + WebP/AVIF.
- التحقق من LCP/INP عبر PageSpeed Insights لأهم 3 أنواع صفحات.

## 5. السيو المحلي (Local SEO) — مضاعِف إقليمي

بما أن النطاق إقليمي، الـ Local SEO رافعة كبيرة:
- **NAP متسق** (الاسم/العنوان/الهاتف) لكل مجمع عبر JSON-LD `MedicalBusiness` (قائم) + ظهوره نصياً.
- ربط كل صفحة مجمع بإحداثيات + خريطة (موجودة `partials/map`).
- صفحات المدن تستهدف عبارات «… في {المدينة}» — وهي صلب نية البحث المحلي.
- (خارج الكود) تشجيع المجمعات على ربط ملف Google Business Profile — يدعم الإشارات المحلية للمنصة.

## 6. مسار B2B (جذب المجمعات للتسجيل)

مسار كلمات مفتاحية مستقل بنية تجارية:
- صفحة هبوط مخصّصة محسّنة لعبارات مثل: «منصة حجوزات للعيادات»، «نظام إدارة عيادات»، «تسويق للعيادات الطبية»، «كيف أسجّل عيادتي في دليل طبي».
- صفحة `/register-clinic` (قائمة) تُحسَّن: عنوان فريد، مزايا، أسئلة شائعة، Schema.
- مقالات موجَّهة لأصحاب العيادات (تسويق طبي، إدارة المواعيد) → تبني سلطة B2B وتغذّي مسار التسجيل.

## 7. استراتيجية المحتوى والسلطة الموضوعية (P3 — طويل المدى)

- نظام المقالات قائم ([ArticleController](../../routes/web.php)) لكنه مربوط بالمجمعات. المقترح: **مركز محتوى للمنصة** (مقالات تحريرية مملوكة للمنصة لا لمجمع) يبني سلطة موضوعية حول التخصصات.
- عناقيد محتوى (Topic Clusters): مقال محوري «دليل تجميل الأسنان» يربط لصفحات التقاطع والمجمعات → ربط داخلي قوي.
- استهداف نية معلوماتية («كم سعر تنظيف الأسنان في الدمام؟») تقود تدريجياً لنية تجارية (صفحة التقاطع/الحجز).

## 8. القياس والمتابعة

- **Google Search Console** + **Bing Webmaster**: رفع الـ sitemap، مراقبة الفهرسة والاستعلامات.
- تتبّع المؤشرات (متوافق مع نظام التتبّع القائم في [docs/tracking](../tracking/gtm-integration-plan.md)، مع الالتزام بعدم إرسال PII/سياق صحي).
- **KPIs المرحلية:**
  - عدد الصفحات المفهرسة (هدف: كل صفحات الكيانات + التقاطعات الصالحة).
  - ترتيب العبارات المحلية المستهدفة (الشرقية).
  - الزيارات العضوية → الحجوزات/طلبات التسعير (B2C) وطلبات تسجيل المجمعات (B2B).
