# الفصل الثاني عشر — البنية التقنية وقابلية التوسّع

## 12.1 لماذا يهتمّ المستثمر بالبنية؟

البنية التقنية ليست تفصيلاً هندسياً فقط — هي التي تحدّد **كلفة التطوير، وسرعة إضافة المزايا، والقدرة على التوسّع، وحجم المخاطر**. هذا الفصل يلخّصها بلغة الأعمال: **منصة حديثة، مبنية بمعايير صناعية، جاهزة للنمو، ومخاطرها التقنية مُدارة**.

---

## 12.2 الحزمة التقنية (Tech Stack)

كلها أدوات **حديثة وسائدة صناعياً** (لا تقنيات هامشية تصعّب التوظيف أو الصيانة):

| الطبقة | الأداة | لماذا |
| --- | --- | --- |
| **الإطار الخلفي** | Laravel 12 · PHP 8.2+ | الأكثر نضجاً وانتشاراً في PHP |
| **قاعدة البيانات** | MySQL 8 | موثوقة وقابلة للتوسّع |
| **لوحات التحكم** | React 19 + TypeScript (صارم) | معيار صناعي، أمان أنواع |
| **أدوات الواجهة** | Vite 7 · TanStack Query/Table | أداء وسرعة تطوير |
| **النماذج** | React Hook Form + Zod | تحقّق قوي من المدخلات |
| **مكوّنات الواجهة** | Radix UI + shadcn | إتاحة (Accessibility) وجودة |
| **السحب والإفلات** | dnd-kit | الكانبان وإعادة الترتيب |

## 12.3 المعمارية: «مصدر حقيقة واحد»

ثلاث واجهات (موقع عام، لوحة مجمع، لوحة إدارة) تشترك في **طبقة خلفية واحدة**:

```
┌──────────────────────────────────────────────────────────┐
│   الموقع العام (Blade)     │   لوحات التحكم (React SPA)     │
│   حارس: web · مريض         │   admin (إدارة) · clinic (مجمع)│
└───────────────┬────────────┴───────────────┬──────────────┘
                │      REST API /api/v1/*     │
                └──────────────┬──────────────┘
                ┌──────────────┴──────────────┐
                │  الخدمات · FeatureGate ·      │
                │  السياسات · المراقِبات ·       │  ← مصدر الحقيقة الوحيد
                │  الكتالوج · الهوية الموحّدة ·   │
                │  الإشعارات · الذكاء الاصطناعي  │
                └──────────────┬──────────────┘
                        ┌──────┴──────┐
                        │   MySQL      │
                        └─────────────┘
```

- **خدمات (Services) مشتركة** تنفّذ كل عملية مرة واحدة.
- **سياسات (Policies)** للصلاحيات، **مراقِبات (Observers)** للأحداث، **إشعارات** موحّدة.
- **واجهة برمجية واحدة (REST API v1)** موثّقة، تخدم اللوحتين.

> **أثر الأعمال:** كل ميزة تُبنى **مرة** وتظهر في كل الواجهات → **أخطاء أقل، أمان أعلى، سرعة تطوير أكبر** → رأس المال يُصرف على النمو لا على إصلاح الازدواجية.

## 12.4 أنماط معمارية تُسرّع المنتج (مزايا مؤسّسية)

طوّر المنتج عدّة **أنماط قابلة لإعادة الاستخدام** تجعل توسعة المزايا شبه مجانية:

- **بوابات مدفوعة بسجلّ (Registry-driven gates):** [مركز الصلاحيات](07-admin-product.md#74-مركز-الطلبات-والصلاحيات-access-center) و[مركز الشارات](07-admin-product.md#76-النمو-المبيعات-والإشعارات-والشارات) — إضافة بوابة/قاعدة جديدة = **سطر واحد** في سجلّ، فتظهر في كل الواجهات والشارات والإجراءات تلقائياً.
- **طبقة هوية موحّدة (Identity layer):** `platform_customers` + أسماء بديلة فوق سجلّات CRM لكل مجمع، يحلّها `PlatformCustomerResolver` من كل نقاط الدخول (حجز/شكوى/تسعير/تسجيل ذاتي).
- **سياق تتبّع واحد (`TrackingContext`):** مصدر حقيقة واحد للبكسلات، مصمّم ليخدم المجمع الآن وصفحات الهبوط/كيانات Trackable مستقبلاً.
- **نظام نماذج موحّد:** مكوّن `Select` قابل للبحث (عربي-آمن) + ملخّص أخطاء أحمر موحّد عبر ~55 موضعاً في الواجهة ونماذج Blade — اتساق تجربة بلا تكرار.
- **نظام بيانات تجريبية (Demo data):** ختم `is_demo`/`demo_batch` + `DemoBatch::wrap` يفصل بيانات العرض عن الإنتاج بأمان ([مركز السيدر](07-admin-product.md#78-الأدوات-التشغيلية-والمستخدمون)).
- **قرّاء جداول مستقلّون:** قراءة CSV/XLSX بلا اعتمادات ثقيلة (ZipArchive مدمج) للاستيراد.

> **القيمة:** هذه الأنماط تعني أن **توسعة المنصة لا تكلّف كوداً يُذكر** — رافعة سرعة وتكلفة مباشرة على النمو.

## 12.5 المصادقة والعزل الأمني

- **Laravel Sanctum (SPA)** بمصادقة كوكيز ذات حالة.
- **ثلاثة حُرّاس منفصلة**: `web` (المريض)، `clinic` (المجمع)، `admin` (الإدارة) — لا تتداخل صلاحياتها.
- **دخول المريض برمز تحقق (OTP)** على الجوال — بلا كلمات مرور. التفصيل الأمني في [الفصل 13](13-security-compliance.md).

## 12.6 قابلية التوسّع (Scalability)

البنية مهيّأة للنمو دون إعادة بناء:

- **طوابير (Queues)** للمهام الثقيلة (إشعارات، مزامنة، استيراد، إعادة بذر) — لا تُبطئ المستخدم.
- **مهام مجدولة (Scheduler)**: تذكيرات انتهاء الاشتراك، مزامنة تقييمات Google، مزامنة Sheets، **إعادة حوسبة الشارات يومياً**، **تذكيرات التواصل والسلال المتروكة**، تذكيرات متابعة المبيعات، تقليم سجلّات الذكاء الاصطناعي.
- **بثّ لحظي (Reverb)** + **Web Push** للإشعارات الفورية.
- **تخزين كائنات (S3-compatible)** عبر Flysystem للوسائط (شعارات/معارض/أغلفة/أيقونات).
- **فهارس قاعدة بيانات** للحقول كثيرة الاستعلام (مزايا الباقة مسطّحة للفلترة السريعة، الهوية بالهاتف المُطبَّع).
- **منع N+1**: خدمات الشارات والإحصاءات تُذاكِر الطلب (request-memoised) لتفادي الاستعلامات المكرّرة.

> التوسّع أفقي ومألوف (طوابير + تخزين كائنات + قاعدة مفهرسة) — لا اختناقات معمارية معروفة.

## 12.7 الجودة والصيانة

- **TypeScript صارم** على الواجهة = أخطاء أقل وقت التطوير.
- **Laravel Pint** لتوحيد نمط الكود.
- **اختبارات (PHPUnit)** + **اختبارات E2E (Playwright)**.
- **Seeders متكرّرة (Idempotent)** لبيانات تجريبية ثابتة، مفصولة عبر نظام البيانات التجريبية.
- **توثيق API مولّد آلياً** (Scribe) يبقى متزامناً مع الكود.

## 12.9 خلاصة الفصل

المنصة مبنية على **حزمة حديثة سائدة**، بمعمارية **«مصدر حقيقة واحد»** و**أنماط مدفوعة بسجلّ** تقلّل المخاطر وتسرّع التطوير، وبنية **قابلة للتوسّع** بأنماط مألوفة. الأهم للمستثمر: **المخاطرة التقنية الكبرى — البناء — انتهت** ([مرحلة التدشين](01-executive-summary.md))، والبنية جاهزة لتحمّل النمو القادم.
